# 可复用打包流程

统一入口为项目根目录 `package.sh`，实现为 `Distribution/package.py`（只使用 Python 标准库）。

```sh
./package.sh                         # 默认双平台
./package.sh macos                   # 仅 Mac
./package.sh windows                 # 仅 Windows
./package.sh all --version 0.2.1      # 指定本次版本，不修改 VERSION
./package.sh --check                 # 本地环境与素材检查
./package.sh --dry-run               # 查看选路、版本与输出位置
```

`VERSION` 是默认版本号唯一来源，Mac Info.plist、Windows 程序版本、文件名与使用说明使用同一版本。旧的两个 `package-*.sh` 仅作为统一入口的兼容包装。

## 固定执行顺序

1. 检查平台、版本格式、构建工具、5 个图案素材和已确认的「hi」应用图标。
2. 获取项目构建锁，防止多个任务同时改写构建目录。
3. 为本次任务创建新的输出目录和工作目录，记录源码提交、脏状态与源码/素材摘要。
4. 构建所选平台，验证运行与包完整性。
5. 检查构建过程中源码和素材未变化。
6. 写入 manifest、校验码和打包记录；仅完成后更新 latest 指针。

## Mac

需要 Apple 芯片 Mac、Xcode Command Line Tools。仅编译 arm64，不构建 Intel 或 Universal 包。应用从干净目录生成，嵌入「hi」手掌 ICNS，并配置 CFBundleIconFile。检查内部版本、单一 arm64 架构、图标配置及原文件校验码、临时签名，再执行本机功能检查。随后用全新暂存目录制作 DMG，附 Applications 入口与中文说明，再验证镜像完整性。

## Windows

需要 .NET 8 SDK；发布自带运行时的 win-x64 单文件程序。

ICO 通过 ApplicationIcon 嵌入程序原生图标资源，同时用于托盘图标；窗口使用对应 PNG。打包检查 EXE 的 RT_GROUP_ICON / RT_ICON 原生资源，逐尺寸比对 ICO，防止仅将图标作为普通素材放入程序却未实际生效。Windows 原生测试同时检查窗口与托盘图标加载。

默认 `--windows-test auto`：Windows 本机执行原生检查，Mac 上通过 GitHub Actions 验证同一源码提交。云端模式要求构建相关文件干净、当前提交已同步到 GitHub；工具可读取当前提交的有效报告，必要时只触发一次工作流，最长等待 15 分钟。已有已跟踪任务失败就停止，不无限重跑。凭据来自 `GH_TOKEN` / `GITHUB_TOKEN` 或现有 Git credential helper；不保存或打印凭据，跨域下载报告不携带 GitHub token。

Windows ZIP 只含 EXE 和使用说明，检查 ZIP CRC、内部文件清单和 EXE 摘要，不夹带 macOS 元数据。云端验证记录明确表示“相同源码提交在 Windows 上原生检查”，本机交叉构建的 EXE 另记摘要，不伪称两个二进制相同。

只有明确接受未验证包时使用 `--windows-test skip`。这会将状态写成 `completed-unverified`，而非 `completed`。

## 输出与失败处理

```text
Distribution/output/<version>/<UTC时间>-<提交摘要>/
  HandTodo-<version>-macOS-AppleSilicon.dmg
  HandTodo-<version>-Windows-x64.zip
  manifest.json
  SHA256SUMS.txt
  打包记录.md
  logs/
  windows-native-test/       # 原生检查报告与截图（如适用）
```

只打一个平台时仅生成对应包。`Distribution/output/latest.json` 指向最近一次完成的任务；失败或中断任务保留自身 manifest 与日志，不覆盖上一次完成任务，也不混用旧包。每次任务使用新目录，产物可追溯。

Mac 当前使用 ad-hoc 签名且未公证；Windows 当前未做 Authenticode 签名。流程不会自动购买证书、签名公证、提交/推送源码、创建 GitHub Release 或上传安装包。个人待办、涂画、图案状态和洗手备份均不进入包。

## 验证打包工具

```sh
python3 -m unittest discover -s Distribution/tests -v
```

修改流程后还需实际运行受影响的平台，以验证真实构建和打包能力。生成的日志和分发包均已被 Git 忽略。
